# Ticker Android v1.1 — Usability & UI Design

Date: 2026-10-14
Status: Approved design (v1.0.x user feedback round)
Prior specs: `2026-10-13-ticker-android-design.md` (v1.0, still binding where not amended)

## Goal

Make the app usable from scratch by someone who has never seen the CLI, and make it look like a market terminal instead of a settings page. Four workstreams from the v1.0.3 feedback round:

1. Symbol input normalization (lowercase phantom entries).
2. Symbol search/lookup across both quote sources (users cannot be expected to know `BTC.CB` exists).
3. Lot editor redesigned list-first (current blank-form-plus-new-button UX is incomprehensible).
4. UI overhaul: dark-first terminal aesthetic, monospace numerics, fixed light-theme contrast.

**Success criteria**

1. Typing `btc` in any add path stores `BTC`; no lowercase entry can ever produce an "unavailable" row.
2. Typing `bitcoin`, `btc`, or `btcusd` in the add-symbol sheet surfaces pickable results across Yahoo and Coinbase forms, labeled by source, without knowing any ticker spelling in advance.
3. "Edit lots" opens showing existing lots immediately; editing requires tapping a lot; exactly one way to add.
4. App defaults to a dark, monospace-numbers terminal aesthetic; light theme is readable (no grey-on-white); theme switchable System/Light/Dark in Settings.

## Hard constraints (inherited, unchanged)

- No GMS/tracking/analytics; no WorkManager.
- Network destinations: **unchanged list** — search reuses `query1.finance.yahoo.com` (already a destination); the Coinbase catalog reuses `api.coinbase.com` (already a destination); the `.X` map already fetches `raw.githubusercontent.com`. No new hosts.
- Foreground-only polling; 30s floor.

## Workstream 1 — Symbol normalization

- `normalizeSymbol(raw: String): String` in `:shared` (`config` package): trim + uppercase (locale-invariant `uppercase()` on the raw ASCII ticker domain is fine; use `uppercase()` without locale args).
- Applied at every entry point: manual add, search-result add, and **on parse** (`parseTickerConfig` normalizes `watchlist` entries and `Lot.symbol` in both YAML and stored-JSON paths). Config files round-trip semantically; symbol case is normalized on load and re-export writes the normalized form (documented divergence — the CLI is case-erratic, Yahoo itself is uppercase).
- Dedupe: `addSymbol`/search-add skip a symbol when the target group already contains it case-insensitively.
- Availability matching in the poller becomes case-insensitive (belt-and-braces for configs written before this change).
- In-app lot/symbol editing paths (index/content capture) are unaffected: they compare against the normalized stored forms.

## Workstream 2 — Symbol search

**Yahoo search client** (`:shared`, `source/yahoo`):

- `GET https://query1.finance.yahoo.com/v1/finance/search?q=<query>&quotesCount=10&newsCount=0&lang=en-US&region=US` with the existing session cookies (no crumb needed; verify live on first wiring) and the same UA/header discipline.
- Response shape to verify live before committing fixtures: `finance.search` returns `{"quotes": [{"symbol", "shortname", "longname", "exchDisp", "quoteType", ...}]}` — field casing is camelCase, distinct from the quote endpoint's lowerCamel `shortName` style; probe and record a fixture, transform to `data class SymbolSearchResult(symbol, name, exchange, sourceTag)`.
- `suspend fun YahooClient.search(query: String): Result<List<SymbolSearchResult>>`; `expectSuccess = false` + sanitized errors per house rules. Errors degrade to an empty result + inline "search failed" note — never block manual add.

**Coinbase catalog** (`:shared`, `source/coinbase`):

- `suspend fun CoinbaseClient.listProducts(): Result<List<ProductCatalogEntry>>` — same market-products endpoint without `product_ids` (full list). **Verify unauthenticated full-list behavior live**; if the endpoint rejects or truncates, fallback catalog = the ticker-static `.X` CSV already fetched by `SymbolsClient` (symbol-keyed, no name matching — acceptable degradation, noted in UI as "symbol match only").
- Catalog entries: `ProductCatalogEntry(productId, baseName, baseDisplaySymbol)`, cached per session (24h TTL, same pattern as the symbol map).

**Mapping to stored symbols** (in `source/Symbols.kt`):

- Yahoo result → store Yahoo's symbol verbatim (it is already canonical for that source).
- Coinbase product → reverse-map through the ticker-static CSV: if a `.X` shorthand exists for the product, propose `SHORTHAND.X`; else propose `BASESYMBOL.CB`. This requires a reverse index (`sourceSymbol → tickerSymbol`) added alongside the existing forward map — first shorthand wins.
- Merge order: Yahoo results first, then Coinbase; dedupe by final proposed symbol; cap 15 rows.

**Search sheet UI** (replaces the plain add-symbol sheet):

- Debounced (300 ms) query ≥ 2 chars; in-flight requests cancelled on new input; per-query results capped.
- Result row: proposed symbol (mono), name (muted), source tag (`Yahoo` / `Coinbase`); tap adds and keeps the sheet open (multi-add, matching the symbols-sheet behavior); added rows get a brief "added" state.
- An always-present last row: **"Add exact symbol… "** — prefills the raw query for manual entry (futures-style or otherwise unknown symbols). Lowercase input is normalized by Workstream 1.
- No results: show "no matches — add `<query>` as an exact symbol" with the same escape hatch.

## Workstream 3 — Lot editor, list-first

- "Edit lots" opens a sheet titled **Lots — <group name>** showing the group's lots as rows: `ARKW  20 @ 145.35  fee 7.00` (mono, quantity/cost right-aligned); empty state: "No lots yet" + one **Add lot** button.
- Tapping a lot opens the editor with fields prefilled (lossless `Double.toString()` values, as today) and **Update** / **Delete** actions.
- The only way to create is **Add lot** → blank editor → **Save**. The blank editor is never the initial state of the sheet.
- Group targeting unchanged: edits act on the selected group (action-time capture, per v1.0 lineage rules).

## Workstream 4 — UI overhaul (dark terminal aesthetic)

**Theme** (`TickerTheme`):

- `ThemeMode { SYSTEM, LIGHT, DARK }` persisted in a settings DataStore key (separate from the ticker config — this is presentation, not `.ticker.yaml` state; exporting it would corrupt CLI round-trips).
- Default: SYSTEM, with dark styles designed first-class; Settings sheet gains a theme picker.
- Dark palette (pinned): background `#0B0E14`, surface `#12161F`, surfaceVariant `#1A1F2B`, onSurface `#E6E9EF`, onSurfaceVariant (muted) `#8B93A1`, positive `#34D399`, negative `#F87171`, outline/divider `#232936`, BTC accent `#F7931A`.
- Light palette (pinned, contrast-fixed): background `#FAFBFC`, surface `#FFFFFF`, onSurface `#171C26`, onSurfaceVariant `#5C6470`, positive `#059669`, negative `#DC2626`, divider `#E3E6EB`, BTC accent `#F7931A`.
- No dynamic color (Material You) — the pinned palettes are the brand.

**Typography — JetBrains Mono, bundled:**

- Font files committed under `composeApp/src/commonMain/composeResources/font/` from the JetBrains Mono release (v2.304, github.com/JetBrains/JetBrainsMono), weights Regular + SemiBold, OFL.txt committed alongside (redistribution permitted).
- **No runtime font fetching** (Google Fonts provider would add a network destination — forbidden).
- Monospace applies to: symbols, prices, quantities, percentages, day-change text, summary bar, positions table, lot rows. Labels/names/body copy stay in the platform sans (readability); headers can stay sans.
- Tabular alignment: right-aligned numeric columns everywhere (quotes, positions, summary, lots).

**Row & surface styling:**

- Quote rows: tighter (48–56 dp), symbol in mono SemiBold uppercase, name in one muted line, price + day-change right-aligned mono; dividers at 8% alpha (or `showSeparator` explicit dividers as today).
- Summary bar and positions section: monospace, table-like right-aligned columns, muted labels, movement-colored values.
- `unavailable` footer and error banner get styled treatments (muted mono, warning-tinted) instead of plain text.
- Sheet surfaces use `surfaceVariant` with 16 dp padding and consistent corner radius.

## Testing

- `:shared:jvmTest`: `normalizeSymbol` + parse-time normalization (YAML + JSON paths, round-trip); case-insensitive dedupe; Yahoo search transform against a recorded fixture (camelCase fields); reverse `.X` mapping; Coinbase catalog transform + fallback; merge/dedupe/cap rules; lot-row model if extracted.
- Live-probe gates (implementation-time, recorded as fixtures): Yahoo search response shape; Coinbase unauthenticated full-list behavior.
- UI changes: `:composeApp:compileKotlinJvm` gate + device smoke by the user (as before).

## Risks

| Risk | Mitigation |
|---|---|
| Yahoo search response shape/fields differ from docs (camelCase `shortname`) | Probe live first, record fixture from the real response, transform only against observed shape |
| Coinbase market-products without `product_ids` may require auth or truncate | Live probe; fallback to ticker-static CSV catalog (symbol-only matching), surfaced honestly in the UI |
| Search adds latency/noise to the add flow | Debounce + cancel + cap; sheet degrades to instant exact-symbol entry on failure |
| Font bundling bloats APK | Two weights, subset if trivially available; ~300 KB acceptable against a 26 MB APK |
| Normalization changes stored user configs on load | One-way, semantics-preserving (case only); export writes normalized form — documented |
